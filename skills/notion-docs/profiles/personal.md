# Profile: personal

## Destination

```
Dashboard → <TBC — likely a "Projects" or "Personal" page> → <Project>
```

**Not yet confirmed.** On first use: search Notion for where personal projects
belong, show Ibrahim the candidates, and ask. **Then write the answer into this
file** and cache the id in `notion-ids.json`.

Covers repos with an `ENG-Sukaiti` remote (e.g. `spotify-music-categorizor`)
and other project directories under `~/gSync/Dev/` outside Hatif.

## Page title

The project name.

## Required sections — starting point, refine with use

1. **What it is** — what the project does and why he built it.
2. **Approach** — stack chosen and why; notable design decisions.
3. **To-do** — checklist. Side projects get resumed after long gaps, so this
   matters more here than anywhere else: leave enough that a cold restart works.
4. **Repos & branches** — where it lives, and the working branch. From git.
5. **Files added** — new files with a one-line purpose each.
6. **Bugs** — sub-page named `Bugs`, same shape as the hatif profile. Optional
   here; create it when the first bug shows up.

## Use as a template

This is the file to copy when adding a new context. Copy it to
`profiles/<name>.md`, edit the destination and sections, then add a routing row
to the table in `SKILL.md`.
